# VOLCMP — FM / ADPCM 音量バランス比較デモ 使用ノート

## 目的

Y8960 は MSX-AUDIO (Y8950) 互換を目指していますが、FM 音源と ADPCM の
音量バランスが実機 MSX-AUDIO とズレているという指摘があります。
VOLCMP.COM は、**実機 MSX-AUDIO カートリッジでも Y8960 カートリッジでも、
まったく同じレジスタ書き込みで動作する** MSX-DOS 用プログラムで、
FM 440Hz と ADPCM サイン波 440Hz を交互に鳴らし、両ハードウェアで
バランスが同じに聞こえるかを耳で比較するための測定用デモです。

## 使い方

MSX-DOS (DOS2) のプロンプトから `VOLCMP` と実行してください。
起動すると ADPCM サンプルをチップの外部メモリに書き込み、
自動で交互再生が始まります。

再生パターン (自動モード):

```
FM のみ 2.5 秒 → 無音 0.5 秒 → ADPCM のみ 2.5 秒 → 無音 0.5 秒 → 繰り返し
```

画面には現在鳴っている音源 (`>> FM` / `>> ADPCM` / `>> (mute)`) が表示されます。

キー操作:

| キー | 動作 |
|---|---|
| `F` | FM のみ連続再生 |
| `A` | ADPCM のみ連続再生 |
| `SPACE` / `B` | 自動交互モードに戻る |
| `ESC` | 全て停止して DOS へ戻る |

タイミングは Z80 3.58MHz 前提で調整しています (1 tick ≒ 33ms)。
turbo R の R800 モードでは周期が比例して速くなりますが、両音源で
同じ時計を共有するため比較の有効性には影響しません。

カートリッジが刺さっていないマシンで実行してもハングしません。
ステータスポート (C0h) が応答しない場合は警告を表示して継続します
(全てのポーリングにタイムアウト付き)。

## 再生パラメータ

### FM 音色 (Ch.1、2 オペレータ、ほぼサイン波、持続音)

| レジスタ | 値 | 意味 |
|---|---|---|
| R#20 (MOD) | 21h | EGT=1 (持続型), MULTI=1 |
| R#40 (MOD) | 1Ch | TL=28 (モジュレータ弱め) |
| R#60 (MOD) | F4h | AR=15, DR=4 |
| R#80 (MOD) | 04h | SL=0, RR=4 |
| R#23 (CAR) | 21h | EGT=1, MULTI=1 |
| R#43 (CAR) | 00h | TL=0 (キャリア最大) |
| R#63 (CAR) | F4h | AR=15, DR=4 |
| R#83 (CAR) | 04h | SL=0, RR=4 |
| R#C0 | 04h | FB=2, CON=0 (FM 接続) |
| R#A0 / R#B0 | F#=580, BLOCK=4 | 439.96Hz、キーオンは B0h=32h |

### ADPCM サンプル

- 波形: サイン波 **440.19Hz** (960 サンプルで 17 周期、ループ境界で連続)
- 符号化: Y8950 ADPCM (4bit)。チップ内デコーダ (予測器 + ステップ表) を
  厳密に再現したエンコーダ (`encode.py`、貪欲法) で生成し、`sample.inc`
  としてソースに取り込み
- 振幅の定義: **ピーク ≈ フルスケールの 70%** を目標に生成。
  デコーダ再現による実測ピーク **23070 / 32767 = 70.4%FS**、
  定常 RMS 16262 (サイン波理論値と一致)
- データ長: 480 バイト。スタートアドレス 0、ストップレジスタ 119
  (アドレスは両チップとも「レジスタ値 × 4 バイト」単位)
- DELTA-N = **8000h**。サンプリング周波数は両チップ共通の式
  `3579545 / 72 × ΔN / 65536` で、**Y8950 でも Y8960 でも
  24,857.95 Hz** (Y8960 説明書の式とも一致を確認済み)
- 再生は R#07 = B0h (START + REC=0 + MEMD=1 + REPT=1) のループ再生
- R#12 (EG / 音量) は**初期値のまま触っていません**。これは意図的で、
  両チップの「素の状態」でのバランスを比べるためです。
  [+]/[-] のレベル調整キーは付けていません (両チップ共通で安全に
  使える静的なレベルレジスタが無く、比較条件を汚すため)

## Y8950 / Y8960 の手順差異と、本プログラムでの扱い

両チップで共通化する際に問題になった点と対処です。

1. **Y8960 は電源投入直後、音源 I/O ポートが全て無効**
   起動時に System Controller (I/O 40h/41h) で Y8960 を検出し、
   C0h が無応答ならスロットを走査して MMIO Enabler2 (7FFFh) の
   OPL2 ビットを立てます。MSX-AUDIO 実機では System Controller が
   存在しないため、この処理は素通りし一切影響しません。

2. **R#04 のフラグマスクと割り込み (実測で判明した最重要点)**
   リセット直後から BRDY フラグは常時立っているため、R#04 を
   アンマスク (00h) したままにすると INT 出力が常時アサートされ、
   DOS 環境が割り込み経路で暴走してハングします (openMSX 上で実測)。
   そのため本プログラムでは通常時 R#04 = **78h (全マスク)** を維持し、
   BRDY ポーリングが必要なメモリ書き込み中だけ、**割り込み禁止 (DI)
   区間の中で R#04 = 70h (BRDY のみ可視化)** します。
   なお「マスクしたフラグはステータス読み出しにも現れない」仕様は
   両チップ共通で、これが上記手順が必要な理由です。

3. **DELTA-N / アドレス単位は両チップで同一**
   サンプリング周波数の式、アドレスの 4 バイト単位、ストップ
   レジスタの扱いはいずれも Y8950 の手順がそのまま Y8960 でも
   成立します (Y8960 説明書第6章と照合済み)。共通手順として
   Y8950 の手順をそのまま採用しています。

4. **レジスタ書き込みウェイト**
   アドレス→データ間 3 DJNZ ループ、データ後 16 DJNZ ループの
   ソフトウェアウェイトを全書き込みで共通使用しています
   (Y8950 の要求を満たし、Y8960 でも問題ありません)。

## 検証記録

- アセンブル: zma v1.0.20、`Success.`
  VOLCMP.COM = **1865 バイト**、md5 `011c22ef1f20c5050691615c8dfde146`
- 動作確認: openMSX 22.0、Panasonic FS-A1ST + Generic MSX-AUDIO
  エミュレーション (Y8950 + サンプル RAM 256KB)、MSX-DOS2 起動
  - バナー表示、ADPCM サンプル書き込み成功 (エラー表示なし)
  - 自動交互再生を 10 周期以上確認 (画面表示で確認)
  - `F` → FM ONLY、`A` → ADPCM ONLY、`SPACE` → AUTO ALTERNATE の
    各切替を確認
  - `ESC` → 全停止して DOS プロンプトへ復帰、ハングなし
- 検証環境 (ヘッドレス) の制約で openMSX の音声録音ファイルは
  生成できなかったため、音量そのものの数値確認は行っていません。
  音の比較は実機で行っていただく前提です (それが本デモの目的です)。
- Y8960 実機での動作は未検証です (エミュレーション環境がないため)。
  Y8960 向けの分岐は検出プローブ + Enabler2 有効化のみで、
  音源レジスタへのアクセスは全て MSX-AUDIO と同一手順です。

## ファイル

- `VOLCMP.COM` — 実行ファイル (MSX-DOS)
- `VOLCMP.ASM` — ソース (zma 形式)
- `sample.inc` — ADPCM サンプルデータ (エンコード済み、ASM から INCLUDE)
- `encode.py` — サンプル生成用エンコーダ (再生成する場合に使用)
