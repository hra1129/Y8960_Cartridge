# Y8960UPD for Windows

USB 接続した Y8960 Cartridge の TangPrimer25K (GW5A-25A) を更新する
WinForms アプリケーションです。.NET Framework 4.7.2 を使用します。

## 使用方法

1. `Y8960UpdWin.exe` を起動します。
2. Config と BIOS の両ファイルを選びます。
   - Config: `Y8960CFG.BIN`（48 バイトの専用ヘッダ付き）。
   - BIOS: `Y8960BIOS.BIN` などの専用ヘッダ付き BIOS。
     このリポジトリでは `tool\bios\MSXSSE.ROM` が該当します。
     ファイル名・拡張子ではなくヘッダとサイズで判定します。
   - 各欄に入力、ファイルをドロップ、または「参照...」で選択できます。
     BIOS 選択ダイアログは `.BIN` と `.ROM` の両方に対応します。
   - 生の `.fs` / `.bin` やヘッダなしの `y8960bas.rom` は選択できません。
3. MSX の電源を切り、TangPrimer25K を USB で PC につなぎます。
   GOWIN Programmer GUI は終了しておいてください。
4. 「次へ」で FPGA の接続を確認し、「書込み開始」を押します。
5. Config → BIOS → 両バージョン情報の順に書き込みます。
   完了するまで USB を抜いたり電源を切ったりしないでください。
6. 正常終了後は FPGA を再起動します。再起動だけ失敗した場合は、
   USB の抜き差しを促すメッセージを表示します。

**この Windows 版では常に Config と BIOS の両方を更新します。**
MSX 版と違い、片方だけの更新は行いません。両バージョンが同じ Flash 消去ブロックに
格納されており、GOWIN CLI の公開操作では他方の情報を読み出して保存できないためです。
対応するリリースの Config と BIOS を組み合わせてください。

## 必要な環境

- Windows 10/11、.NET Framework 4.7.2。
- GOWIN Programmer と USB ドライバー。
- Arora V の exFlash 操作に対応する `programmer_cli.exe`。
  操作番号は GOWIN Programmer V1.9.12.03 のヘルプで確認しています。

CLI は前回の指定、PATH、各固定ドライブと Program Files の Gowin 配下から検索します。
見つからなければパスの指定画面を表示します。接続画面の「CLI の変更...」でも変更できます。
指定先は `%LOCALAPPDATA%\Y8960UpdWin\programmer_cli_path.txt` に保存します。
FPGA 型番を確認できない場合、GW5A-25 系以外の型番が検出された場合、複数台が検出された場合は書き込みません。
(programmer_cli は GW5A-25A/25B/GW5AS/GW5AR を「One of them」として並べて表示しますが、これは正常です。)
書き込み直前にも接続を再確認します。

## ファイル形式・書き込み先

形式、サイズ、Flash アドレスは `tool\y8960upd.asm` の仕様に合わせています。

| 対象 | シグネチャ（32 バイト、残りは 00h） | 本体サイズ | Flash 書き込み先 |
|---|---|---|---|
| Config | `Y8960_TP25K_CARTRIDGE` | 1～7D0000h バイト | 000000h～ |
| BIOS | `Y8960_BIOS_IMAGE` | 20000h バイト（128KB） | 7E0000h～7FFFFFh |

両形式とも +32 に 16 バイトのバージョン、+48 以降に本体があります。
ヘッダは Flash の本体領域には書き込みません。

本体は非圧縮（従来形式）と ZX0 ブロック圧縮のどちらでもよく、本ツールと
MSX 版ツールのどちらも両形式を受け付けます。形式はシグネチャの最終バイト
（+31）の形式マーカーで区別します（0 = 非圧縮、1 = 圧縮。それ以外は不正な
ファイルとして拒否します）。上表の本体サイズは伸長後のサイズで、サイズの
判定（Config の上限、BIOS は 128KB ちょうど）は伸長後に対して行います。
なお旧バージョンのツールはシグネチャ全体を照合するため、圧縮ファイルを
書き込まずに弾きます。

圧縮形式の +48 以降のレイアウトは次のとおりです。

- +48 に伸長後の本体サイズ（uint32 LE）、+52 にブロックサイズ
  （uint16 LE、16384）。
- +54 以降はフレームの繰り返しで、伸長後の本体サイズ分を生成すると
  ちょうどファイル終端になります（末尾の余分なデータは不正です）。
  - 各フレームは長さワード（uint16 LE）から始まります。最上位ビットが
    1 の場合は無圧縮ブロックで、下位 15 ビットがそのまま長さです。
  - 最上位ビットが 0 の場合は ZX0 圧縮ブロックで、ワードの値が圧縮
    データの長さです。各ブロックは独立した ZX0 ストリームで、ブロック
    サイズ（最終ブロックは残りサイズ）に伸長されます。
  - 圧縮しても小さくならないブロックは、無圧縮ブロックとして格納されます。

圧縮ファイルは `tool\zx0pack` で生成します（`tool\config\mk.bat` と
`tool\bios\mk.bat` から呼ばれ、ヘッダは従来どおり `header.bin` です）。

1. Config 本体を `000000h` に書き込み、ベリファイします。
2. BIOS 本体を `7E0000h` に書き込み、ベリファイします。
3. 両方成功した場合だけ、64KB のバージョンブロックを `7D0000h` に書き込みます。
   - `7DFF00h` に Config のバージョン 16 バイト。
   - `7DFF10h` に BIOS のバージョン 16 バイト。
   - 残りは FFh。
4. `--run 1` で FPGA を再起動します。

書き込みにはすべて次の形式を使います（アドレスとファイルは工程ごとに変わります）。

```text
programmer_cli --device GW5A-25A --frequency 2.5MHz --run 54 --fsFile "config.bin" --spiaddr 0x000000
```

`54` は **exFlash Erase,Program,Verify Arora V** です。
専用ヘッダを除いたバイナリを `--fsFile` で渡し、`--spiaddr` に書き込み、ベリファイします。
RISC-V C Bin 用の操作 `56` は使用しません。このツールの入力指定では、
終了アドレス 0 のまま `Program and Verify Flash Failed!` になりました。

GAO-Bridge 経由の操作 (`67`～`69`) は使用しません。
- ブリッジ選択には .fs ヘッダの `Device-package` が必要です。
  このツールの .bin を渡すと `No gao bridge files found for this development board` で失敗しました。
- 実機確認では、ヘッダ付き .fs を与えるとブリッジは読み込めました。
  しかし GOWIN 生成の .fs でもブリッジ経由のベリファイ (`67`) が先頭から不一致になりました。
- ブリッジなしのベリファイ (`66`) では、Config 本体の先頭 1024 バイトを .bin で渡すと照合に成功しました。
  同じデータを .fs にした場合も成功し、512 バイト目を 1 ビット変更した負対照はページ 2 で失敗しました。
  これは入力解釈と先頭範囲の読み出しの確認であり、全領域の書き込み成功を保証するものではありません。

## エラー・進捗

- ファイル不正、シグネチャ違い、サイズ違いでは接続確認へ進みません。
- CLI の異常終了および出力の Error / Verify failed などを失敗と判定します。
- 消去・書き込み・ベリファイの工程に応じて
  `Erase error.` / `Write error.` / `Verify error.` と出力末尾を表示します。
- 失敗すると後続の書き込みと再起動は行いません。
  本体の書き込み失敗時は、バージョンブロックを更新しません。
  ただし **本体やバージョンブロックのロールバックはできません**。
  既存のバージョン表示が残っていても、Flash の内容が正常とは限りません。
  MSX を起動する前に両ファイルで更新を完了してください。
- 進捗は Config 0～75%、BIOS 75～88%、バージョン 88～97%、再起動 97～100%。
  CLI が割合を出さない場合は経過時間から推定します。
- Flash に書き込まれている現在のバージョンは読み出しません。

## ビルド・テスト

Visual Studio 2022 / .NET Framework 4.7.2 開発環境で `build.bat` を実行するか、
`Y8960UpdWin.sln` を開いて Release ビルドします。
`Y8960UpdWin.exe` をこのフォルダへ出力します。

テストは `tests\Y8960UpdWin.Tests.csproj` をビルドして実行します。
偽の CLI を使用し、ファイル検査、書き込みデータ・アドレス、実行順、GUI の正常経路と
各工程の失敗時の中断（終了コード 0 のエラーを含む）、再接続確認の失敗、
再起動だけの失敗を確認します。
実機や USB にはアクセスしません。

**Y8960 での実機書き込みは未検証です。** 元の V9968 ツールの実機確認結果は引き継ぎません。
