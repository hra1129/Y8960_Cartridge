# Y8960upd
	MSX-DOS上で動作する Y8960 Cartridge Update Tool である。
	実行ファイル名は Y8960UPD.COM である。

# Usage
	/H, /? が指定された場合、あるいは引数なしの場合には Usage が表示される。
	System Control にアクセスし、Y8960 Cartridge が装着されていない場合は、
	その旨表示して DOSへ戻る。

	> Y8960UPD
		引数無しで起動し、かつ Y8960 Cartridge を検知した場合は、
		ConfigROM, BIOS のバージョン情報を表示する。

		Cfg. Ver: {Config data バージョン情報文字列}
		BIOS Ver: {BIOS data バージョン情報文字列}

	> Y8960UPD /C y8960cfg.bin
		y8960cfg.bin が、Y8960 Cartridge用の Config data であるか確認し、
		Config data であると認知した場合に、ConfigROM の 000000h- にその内容を書き込む。
		Config data には、専用のヘッダをつけて置き、それで認知する。
		書き込むデータはそのヘッダの後についている。
		そして、対応する Config data のバージョンを 7DFF00h- に書き込む。

	> Y8960UPD /B y8960bios.bin
		y8960bios.bin が、Y8960 Cartridge用の BIOS data であるか確認し、
		BIOS data である場合は、ConfigROM の 7E0000h- にその内容を書き込む。
		そして、対応する BIOS data のバージョン情報を、7DFF10h- に書き込む。
		(この際、Config data のバージョンが消えてはだめなので、7DFF00h- をバックアップとっておき、
		消したら

	ConfigROM の 7DFF00h- の 16byte には Config data のバージョン情報文字列、
	ConfigROM の 7DFF10h- の 16byte には BIOS data のバージョン情報文字列、
	が記録される。

# Config data header
	+0	"Y8960_TP25K_CARTRIDGE" (残り +30 までは 00h を詰める。+31 は形式マーカー)
	+32	Config data バージョン情報文字列
	+48	Config data 本体

# BIOS data header
	+0	"Y8960_BIOS_IMAGE" (残り +30 までは 00h を詰める。+31 は形式マーカー)
	+32	BIOS data バージョン情報文字列
	+48	BIOS data 本体 (128KB)

# 圧縮形式 (ZX0 ブロック圧縮)
	ヘッダ +31 の形式マーカーで本体の形式を示す。マーカー以外の
	シグネチャ余白 (+30 まで) は従来どおり 00h を詰める。

	+31	形式マーカー
		00h: 非圧縮 (従来形式。本体は +48 以降にそのまま格納)
		01h: ZX0 ブロック圧縮 (下記)
		それ以外の値は不正なイメージとしてエラーになる。
		旧バージョンのツールはシグネチャ32バイト全てを照合するため、
		圧縮形式のファイルは旧ツールではエラーになり、誤って
		書き込まれることはない。

	マーカーが 01h の場合、+48 以降は次の構造になる。

	+48	本体の元の (非圧縮時) サイズ (uint32 little-endian)
	+52	ブロックサイズ (uint16 little-endian、16384)
	+54	フレームの繰り返し (元のサイズ分を出力するまで)

	各フレームは、長さワード (uint16 little-endian) とデータからなる。
	- 長さワードの bit15 が 1: 無圧縮格納ブロック。
	  長さは (ワード & 7FFFh) で、その直後に本体データがそのまま続く。
	- 長さワードの bit15 が 0: ZX0 ブロック。
	  長さはワードの値 (1〜16384) で、その直後に ZX0 形式の
	  圧縮データが続く。1ブロックが独立した ZX0 ストリームであり、
	  伸長すると元の本体のうちブロックサイズ分 (最終ブロックは残り分)
	  になる。

	生成側 (パッカー) は、ZX0 圧縮で小さくならないブロックを
	無圧縮格納にする。そのため、どのフレームのデータ長も
	16384 バイトを超えない。

	Config / BIOS ともに、サイズの検査 (Config は 1〜7D0000h バイト、
	BIOS は 20000h バイトちょうど) は伸長後の元のサイズに対して行う。
	Y8960UPD.COM は、非圧縮・圧縮のどちらのファイルも受け付け、
	圧縮ファイルはブロック単位で伸長しながら書き込む。

# ソースコード
	MITライセンスのヘッダを冒頭に付け、ZMA でアセンブルできる Z80プログラムとする

# ビルド
	zma.exe 使ってアセンブルし、Y8960UPD.COM を生成する

# ベリファイ失敗時の表示
	不一致を検出すると、Flash のアドレス、期待値、実読値、および直前の完了待ちで読んだ
	ステータスレジスタ1の値を表示して終了する。表示例:

	Verify error at 7E0000h: expected 41h, read FFh (last SR1=00h).

	この例では 7E0000h に 41h を期待したが FFh が読めたことを示す。
	last SR1 は直前の書き込み・消去の完了待ちで最後に読み取った値であり、
	不一致アドレスへの書き込み直後の値とは限らない。
	ベリファイ失敗時は、バージョン領域を更新しない。

	消去では、各ブロックについて次の 2 点を確認し、満たさなければその時点でエラー終了する
	（書き込みもバージョン更新も行わない）。
	- 消去コマンド後の完了待ちで BUSY=1 を一度でも観測したこと。64KB 消去は数ms 以上かかるため、
	  観測できない場合は ConfigROM がコマンドを無視した（書き込み保護など）とみなす。
	    Erase was not accepted (BUSY never set, SR1=00h).
	- ブロック先頭 256 バイトが FFh であること（簡易ブランクチェック）。
	    Erase check failed at 7E0000h: read 41h (last SR1=00h).
	消去時の OK は上記を満たしたことを示すもので、ブロック全バイトの検査ではない。
	BIOS 更新失敗時は Flash 内の BIOS が未完成の可能性があるため、
	書き込みを完了するか復旧手段を確保するまで MSX をリセットしないこと。

# BIOS 不良時の切り離し起動
	DIPSW[1] に対応した RTL では、OFF でカートリッジの I/O・ROM/RAM アクセスを
	遮断し、データ出力・WAIT・割り込みも無効にする。ON で通常接続になる。
	電気的には OFF が 1（FPGA 内蔵プルアップ）、ON が 0（GND 接続）。
	切り替えは約 1.5ms のチャタリング除去を行い、接続は /RD と /WR が共に
	非アクティブになってから行う。

	BIOS の更新失敗により MSX が起動しない場合は、次の手順で診断環境へ戻れる。
	1. この切り離し機能を含む FPGA データを書き込む。
	2. 電源を切った状態で DIPSW[1] を OFF にし、MSX を DOS まで起動する。
	3. DOS 起動後に DIPSW[1] を ON にする。MSX のリセットは不要。
	4. 通常は起動後の BIOS コピーは完了済みだが、コピー中なら接続後は WAIT が働く。
	   System Control の読み戻し確認など、書き込みを伴わない診断から再開する。

	DIP 切り替えでは内部リセットや BIOS の再コピーは行わず、
	起動時の Flash → SerialSRAM コピーは切り離し中も継続する。
	書き込み途中のアクセスを中断する可能性があるため、更新処理中は切り替えないこと。
	この機能は Verify error の原因を修正するものではない。
	BIOS の書き込みとベリファイに成功するまでは、次回起動も OFF にしておく。
	更新した Flash の BIOS を SerialSRAM に反映するには、その後のリセットが必要。
